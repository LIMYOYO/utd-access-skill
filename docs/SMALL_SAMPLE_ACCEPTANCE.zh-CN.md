# 0.6.0 真实浏览器小样例验收

测试日期：2026-10-02。环境：macOS、已登录的 Chrome、多大 LibKey Nomad → EBSCO，以及 SSRN 正常下载入口。使用当前仓库构建的 `0.6.0.dev1` wheel 和 `0.6.0` 扩展，默认 `advisory` 身份策略。

结果：4 篇真实论文全部下载成功且身份校验通过；一个故意无效的 DOI 在并行组内独立失败，两个成功文件保留，下一项 SSRN 请求正常完成。没有手工代点论文下载按钮。

## 1. 样例结果

| 来源 / 场景 | 标识 | PDF 页数 | 结果 |
| --- | --- | --- | --- |
| INFORMS 单篇 | `10.1287/mnsc.2018.3061` | 16 | `download_status=complete`、`identity_status=verified`、`analysis_allowed=true` |
| INFORMS 并行组 | `10.1287/mnsc.2018.3148` | 28 | 下载和身份校验通过 |

`10.1287/invalid.release-smoke` 是人为构造的无效测试标识，不是论文引用。并行组以 `--concurrency 3` 一次提交这三个标识。

另测试了非法输入 `not-a-doi`：0.26 秒返回 `invalid_informs_doi`，没有任务 ID，也没有写入下载队列。

## 2. 时间与文件检查

- INFORMS 单篇：29.11 秒。
- 两篇正常论文与一个失败样例的并行组：154.34 秒。整组耗时包含失败样例的超时等待；两篇正常论文提前完成，不能把 154 秒当作纯成功批量的耗时。
- SSRN 单篇：14.46 秒。

以上是 CLI 提交到返回的墙钟耗时，包含本次网络、浏览器和校验开销，不是速度保证。

逐份检查了 PDF 文件存在、`%PDF-` 文件头、页数、SHA-256 和晚于本次请求创建时间的落盘时间，确认没有把此前的交付文件作为本次结果。三份 INFORMS 文件正文均含对应 DOI；SSRN 文件以标题、作者和正常下载来源完成程序身份核对。所有成功结果都允许后续分析。

失败组结束后，SSRN 请求可立即进入队列并成功完成。结束时活动请求数为 0，bridge 的 `installed`、`connected`、`download_root_exists` 均为 `true`。

## 3. 测试版本与范围

测试前保留旧 runtime 和扩展备份，再更新原扩展加载目录，保留扩展 ID 和现有来源权限。逐文件比较确认加载目录的 manifest / JavaScript 及新 runtime 的 Python 源码与本次仓库一致，然后 Reload 扩展完成连接。没有改动学校登录信息。

本次证明的是这台机器、当前学校会话和四篇已知可访问论文的小样例流程。未覆盖新机器首次安装、所有 INFORMS 期刊、订阅缺失、登录失效、验证码出现、运行中断开重连或长期连续运行。所有成功样例身份均通过，因此真实浏览器样例没有单独覆盖身份未通过时的 advisory / strict 差异；该差异由 `tests/python/test_delivery_policy.py` 的合成 PDF 回归测试覆盖。

论文 PDF、私有任务 JSON、数据库和本机路径保留在用户运行目录，不纳入仓库或发布包。
